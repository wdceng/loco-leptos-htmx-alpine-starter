# Review recent work

With ultracode on, a workflow, one agent a group of passes, each finding read a second time; with it off, inline, one focused pass, one subagent at most (the maintainer's rules: `CLAUDE.local.md`, `~/.claude/CLAUDE.md`). An agent runs no cargo command.

## The project's list first

Read `.claude/review.md` in the project's root before anything else: the project's own names for each pass (its helpers, its permission and cross-site checks, its guard file, its scripts, its docs, its lanes), the passes that do not apply with their reason, and its dated incidents. Below, "(the list)" means a name or a file found there. No list: say so and stop; a new project copies the starter's.

## Scope

- A finished task: its branch's diff against its epic's branch, or the branch it came from, and nothing else.
- The commits the maintainer names, a branch, or the whole project. Otherwise `git log --oneline -20`, and the commits since the last review's fixes; ask when the start is unclear.
- Plus what is not committed yet: `git status --short`, `git diff`.
- Read the diff (`git diff <base>..HEAD`), then each touched file in full around every change.

## Passes

The same seventeen, in this order, in every project, so a pass's number means one thing everywhere. A pass the list marks as not applying is named in the report's clean line with that reason.

1. **One-job drift**: one job done two ways, in the code or in what a visitor sees (the look, the motion, the words); the project's register of jobs first (the list). Its kind named: DRY, logic or words written twice; single source of truth, one fact (a limit, a name, a size) decided in two places; snowflake, a one-off built beside the shared component. Also a helper the diff should have used (the list); a job with no row in the register; a drift that could come back, with its guard proposed for the guard file (the list), its pattern and its one home.
2. **Redundant**: dead code, a branch that cannot happen, a parameter nobody passes, a dependency or a `web-sys` feature nothing uses, a test that repeats another, a comment that says what the next line says, code that would be simpler doing the same thing.
3. **Bugs**: `unwrap()` or `expect()` on the request path; an error path that drops the user's input; two requests at once, a double click, two tabs, a stale page, a preloaded page racing Alpine's state (an element whose click sends a request sets the state its page will draw, never flips it); a transaction outside the project's one way to write (the list); an inline `style=` or script; a rule of the visitor's language broken (the list); a link not from the project's paths (the list); a move in place that loses the focus, the title, the scroll or the `:target`; a file in `public/` changed without a new address (a year-long cache); a page held open across a deploy without the build's check; a quoting bug or an unguarded `rm` in a shell script (the list).
4. **Security**: the project's security doc read first (the list), and a session, header or CSP change given its line there; a protected page without its permission check, a post without the cross-site check (both the list); a rate limit skipped; a value not bound in SQL; a visitor's value unescaped in a mail (Loco's Tera templates do not escape `html.t`), or a mail's recipient or header taken from the request; a staged `secrets*.env`; a secret in a log, a `#[instrument]` among them, which records every argument unless it `skip`s the password, the token, the key, the body, a form or an upload.
5. **Leaks**: an island htmx takes off the page without its `$$dispose` called; Leptos's timer helpers in an island in place of the project's own scheduling (the list); a window listener not removed in `on_cleanup`; a closure forgotten (`forget()`) instead of kept with its owner; a `thread_local!` holding a page's state rather than the visit's; a process a script starts (the list) and does not stop on every path.
6. **htmx and Alpine under the CSP**: `hx-on`, a `js:` value or a trigger filter (they need `'unsafe-eval'`, so they never run); full Alpine in place of its CSP build; a global (`window`, `navigator`, `document`, `location`), a statement or a string `:style` in an Alpine expression, or a quote from the server inside one; `Alpine.data`, `Alpine.store` or a script of our own beyond the project's hand-written helpers (the list); Alpine and an island on one element; an island inside what htmx swaps on its own (`every …`); an attribute meant for the children without `:inherited`.
7. **Accessibility**: a control with no name, or a name that does not start with its visible text (WCAG 2.5.3); text in another language without its `lang`; a live region missing or doubled; the focus lost after a swap; a tap target under 44px; a refused form without its refused field's title and `aria-describedby`; a colour not from the role tokens, or a role's contrast broken in the light or the dark scheme.
8. **Performance**: work on every request that could be done once at boot; an image on the first screen loaded lazily, or one below it eagerly; a photo without its widths or its placeholder; a font without its `unicode-range` subset; a query a row in a loop, where one read of every row it needs into a `HashMap`, compared in memory, and only the differences written would do; the same key looked up again a row, where `HashMap::entry` keeps its first answer; a list with no limit; the WASM bundle growing (its budget, the list); an island not lazy that only some pages use, or rendered where it is not needed.
9. **Async**: the project's async doc read first, its table and every gotcha (the list). Checked:
   - queries that wait for no other in one `try_join!`, each on a connection of its own, never two in one transaction, which runs them in turn; a chain that depends on its order an async block in the join;
   - CPU work (an encoder, a hash, SHA-256 too, a parse of megabytes) in `spawn_blocking`, a data-parallel loop over a big slice `rayon` inside it, never on the async threads; a password hash through the project's one way (the list), made before a transaction;
   - a `spawn_blocking` inside `try_join!` its `JoinError` flattened in the branch; a cap's permit moved into the task with the work, since a dropped one runs on;
   - nothing blocking an async thread: no `std::fs`, `std::thread::sleep`, or `std::sync::Mutex` held past a quick change; a lock held across an `.await` a `tokio::sync::Mutex`, and then what queues behind it named; the line, Tokio's: no more than 10 to 100 µs between two `.await`s, so a loop over many rows that awaits nothing is blocking too;
   - a `spawn_blocking` cannot be aborted once it runs, and a shutdown waits for it: a long one has its own end (a deadline, a check between rows), never a loop that runs on;
   - work that must finish its own `tokio::spawn` with `.instrument(tracing::Span::current())`; nothing relying on work after the answer, which a shutdown cuts off; where it should finish anyway, a `TaskTracker` the shutdown waits on, named as a choice;
   - per-request state in a `task_local!`, where an extractor or the handler's argument would carry it in the open;
   - a `timeout` on anything outside the process, at the async doc's values; something heavy behind a `Semaphore`; many tasks a `JoinSet` under one `timeout`; writes that belong together one transaction;
   - the tool a change needed and did not use: `join!` where no branch can fail, `select!` for the first of several (a clock, a shutdown), a channel between tasks (`mpsc` a queue, `broadcast` every reader each message, `watch` the latest value), a `CancellationToken` for a long job a shutdown or a person stops;
   - two or more `.await`s in a row that wait for no other: the finding, and a guard proposed for the guard file that fails on the pattern within a few lines of one file, with an allow list and each entry's reason.
10. **Depth and props**: a repeated subtree inside an island's children not cut by a component returning `.into_any()`, never by raising `recursion_limit`; an island prop that carries content (text, markup, a list to draw), where `children` would render it on the server: a prop is serialized into the page as JSON and read again in the browser, so its data is sent twice. A project stricter than that (no prop at all beside `children`) says so in its list.
11. **Policy and pages**: a config change that alters policy (headers, CSP, rate limits, cache, timeout) without the config test (the list); a layer added in code (`middleware::from_fn`, `route_layer`, a tower layer) where Loco's config already has one for the job, or one with no test pinning it; a new resource kind without its CSP directive in every config; a new public page that matters without its link in `/llms.txt` (the list).
12. **Docs**: a sentence the change made false in CLAUDE.md or the feature's doc (the list); a section changed in one of the parallel deploy docs (the list) and not the others; a tool or build decision without its dated line in the decisions doc (the list).
13. **Tests**, each change's own, at every level it touches: a new branch with no request or unit test; browser behaviour with no e2e test on its lane (written, not run), and an optimistic control with no in-between test (pass 17); something only the app does (a plugin, a push, a link handed to the system) with no test on the app's lanes; the app's own Rust (`src-tauri/`) with no unit test; an island's pure logic with no unit test, native or WASM (`#[wasm_bindgen_test]`) where it needs the browser; a touched island's failure, refusal and cleanup paths with no test, not only its main path. The whole project's sweep is `/test-coverage`.
14. **Rust's own guarantees**: where the compiler could hold a rule a person holds now. A `String` or `bool` where an `enum` or newtype would make a wrong value impossible (a status as text, two flags that cannot both be true); a job's insides `pub` where private would keep the job to its one way; a `_ =>` that would swallow a new variant where listing them makes the compiler point at every place; an error logged and gone on from, or an `Option` turned into a default that hides the missing value, where `?` and a typed error would do; a `.clone()` on the request path where a borrow would do; a function that returns a new `String` for text it mostly leaves as it was, where `Cow<str>` would hand the input back; a string built once and cloned on many requests, where `Arc<str>` would share it; something both halves compile that belongs behind the `ssr` gate; an index loop where an iterator says the intent; a result a caller must not drop without `#[must_use]`; a public enum other crates match on, where `#[non_exhaustive]` should keep a new variant from breaking them, or one they must match in full, where it should not; a public type without `Debug`, or an error type that says nothing of what failed.
15. **Axum**: input read by a typed extractor (`State`, `Path`, `Query`, `Form`, a struct with real types) where a handler parses strings by hand; the body's extractor (`Form`, `Json`, `Bytes`, `String`, `Multipart`) not the last argument, or two of them; an `Extension` where `State` would do, a missing one a `500` at run time where `State` fails the build; an `Option<…>` extractor read as "absent or wrong", where a malformed value still refuses the request; a check every handler repeats in its body (`else { return … }`) where an extractor of its own, `FromRequestParts` with `Rejection = Response`, would answer the 403 or 404 itself; a route that takes an upload without a body limit of its own, or a small form under the upload's limit (axum's default is 2 MB); a large answer (an export) built whole in memory where a streamed body would do; a handler's error a typed one turned into the answer, never a `500` hiding a `400`.
16. **A framework's own tool**: Loco, Leptos and their crates each bring a tool for a job the project already does its own way; one that appears is a second way (Rule no. 1), named with the one it would sit beside (the list) and asked about, never added quietly:
    - Loco's background workers (`BackgroundWorker`, `perform_later`) beside `tokio::spawn`; its scheduler, its cache (`cache_inmem`, `ctx.cache`) and its storage (`ctx.storage`) beside the project's own;
    - a Leptos server function (`#[server]`) beside Loco's controllers: a second door to the server, with its own address, outside the permission checks, the cross-site check and the rate limiter;
    - Leptos's `Resource`, `Suspense` or `Action` beside htmx: data fetched in the browser and sent twice, and a bigger WASM bundle.
17. **One fact drawn twice**: a fact (a quantity, a status, a choice, an on/off) the server draws in several places or forms (a number, an icon, a label, an `aria-label`, `disabled`, empty vs full, an open fold), checked at three moments (the split-state audit of an islands app on this stack, 2026-11-10, 31 found):
    - at the tap: what an island or Alpine changes before the answer, against every detail the server draws for that fact; one it does not switch shows the old state until the answer. The fix is every state drawn by the server and switched by one attribute (`group-data-*`, `group-aria-*`), never a detail copied into the browser;
    - at the answer: every part on the page showing the fact is in the swap (`hx-select-oob`, the project's own swap list); one left out stays stale until a reload; two polls on one page are one clock;
    - at a failure: a failed or refused request leaves no browser guess on screen (a queued tap, a drag, a crop, a switch); it goes back to the server's truth in one place;
    - and its test: an e2e test holding the server's answer, reading the part at the tap, then letting the answer through and comparing the part after it, the two equal.

Any pass or group runs alone: `/review <scope>, <passes> alone` (`/review the whole project, the async pass alone`). The whole project goes in groups, not all seventeen at once.

## Proof

Every finding is checked in the code before it is reported, by reading or by a test that shows it, with the case that fails; a doubt is reported as a doubt.

## Report

One table, most severe first:

| # | Kind | Where | What is wrong | Fix |
| --- | --- | --- | --- | --- |

The kind is a pass's name (DRY, single source of truth or snowflake for a drift); every file a clickable link with its line. Under it, what was checked and found clean, in one line, with the passes the list marks as not applying. On a finished task, no table and no question: its findings are fixed in the task, the larger ones named in the handover. Otherwise, one question: "go all", "go 1, 3" or "skip". Nothing is edited before the go; after it, the fixes, the checks, the task branch's commit and push, and its run (the maintainer's rules, Handing over).

## The list's shape

`.claude/review.md`, in the project's git, short: a heading a pass that has names of its own (`## 4 Security`), under it the names and files, a pass that does not apply its one line and reason (`## 6: no Alpine in this project`), and a last heading for the dated incidents a pass should remember. Nothing the skill already says is repeated there.
